# 智能图库 · astrbot_plugin_smart_image

一个给 [AstrBot](https://astrbot.app) 使用的跨平台图片库插件。

它把“图片”变成可检索、可学习、可管理的资产：在聊天里直接上传，给图片打标签，之后按标签随机发图、搜索发图，或者让机器人听到关键词后自动发图。所有发送都走 AstrBot 统一消息链，不写任何平台专用 API。

## 功能

- **聊天上传**：附带图片发送指令即可入库，也支持引用一条含图片的消息。
- **链接导入**：管理员可把 http/https 图片导入图库（默认禁止普通成员使用）。
- **标签检索**：按标签、描述、自由文本搜索；支持分页列表、详情、改标签。
- **随机 / 自动发图**：`/图库 随机 猫`；开启自动模式后，消息命中标签自动配图。
- **自学习**：
  - 学习模式下，群友发的“图片 + 文字说明”会自动入库，文字成为标签/描述。
  - 自动发图后，用户回复“好可爱 / 不对”等会调整推荐权重；正面短词会被学习成新标签。
- **自管理**：
  - 容量上限、低价值图片自动移入回收站、回收站恢复、过期清理。
  - 失效索引 / 孤立文件修复。
  - 去重：同一张图重复上传只合并标签，不占额外空间。
  - 标签、启用状态、上传者权限管理。
- **全平台**：使用 AstrBot 的 `Image` 消息段与 `event.chain_result`，兼容 OneBot、QQ 官方、Telegram、Discord、飞书、企业微信、Slack、KOOK、Satori、Matrix、WebChat 等适配器。
- **零额外依赖**：只使用 AstrBot 自带能力；Pillow 存在时读取尺寸，不存在也不影响使用。

## 安装

### 方式一：WebUI 上传 ZIP（推荐）

1. 打开 AstrBot WebUI。
2. 进入 **插件** 页面，点击 **安装插件**。
3. 选择本仓库打包的 `astrbot_plugin_smart_image.zip` 并上传。
4. 安装完成后启用插件，必要时重载。

ZIP 内顶层目录为 `astrbot_plugin_smart_image/`，包含 `metadata.yaml`、`main.py`、`_conf_schema.json` 等文件；AstrBot 会自动展平该目录。

### 方式二：手动解压

把 `astrbot_plugin_smart_image/` 整个目录放到：

```text
AstrBot/data/plugins/astrbot_plugin_smart_image/
```

然后重启 AstrBot，或在插件页重载。

### 更新后装不上

v1.1.0 已针对 ZIP 安装做了两项兼容修复：

- `main.py` 不再使用相对导入，而是按文件路径加载 `core.py`；
- `metadata.yaml` 去掉了强制的最低版本限制，并升级版本号。

如果仍提示已存在/安装失败：

1. 先禁用插件，删除 `AstrBot/data/plugins/astrbot_plugin_smart_image/`（不要删除 `data/plugin_data/astrbot_plugin_smart_image/`，图片数据在那里）；
2. 再上传新的 `astrbot_plugin_smart_image.zip`；
3. 确认 ZIP 没有解压成 `astrbot_plugin_smart_image/astrbot_plugin_smart_image/` 的嵌套目录；
4. 查看 AstrBot 日志里的真实报错（常见是旧目录残留或 `ImportError`）。

## 快速开始

在私聊或群里（群聊需要 @机器人 / 唤醒词）：

```text
/图库 上传 猫 橘猫 | 一只在窗台睡觉的橘猫
```

发送时附带一张图片，或用“引用”回复一张图片。

之后：

```text
/图库 随机 猫
/图库 搜索 橘猫
/图库 列表
/图库 自动 开
```

开启自动模式后，群聊里 @机器人 说“来张猫图”，插件会按标签匹配并发送。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/图库` / `/img` / `/image` | 显示帮助 |
| `/图库 上传 <标签...> [\| 描述]` | 附带/引用图片上传，标签用空格或逗号分隔 |
| `/图库 链接 <URL> <标签...> [\| 描述]` | 从 http/https 链接导入（默认仅管理员） |
| `/图库 学习 <标签...> [\| 描述]` | 与上传相同，来源标记为“手动学习” |
| `/图库 随机 [标签]` | 随机发送一张，可按标签过滤 |
| `/图库 搜索 <关键词>` | 搜索并预览前几张 |
| `/图库 列表 [页码]` | 分页列出图库 |
| `/图库 详情 <ID>` | 查看标签、描述、上传者、统计 |
| `/图库 改标签 <ID> <标签...> [\| 描述]` | 替换标签，可同时改描述 |
| `/图库 加标签 <ID> <标签...>` | 追加标签 |
| `/图库 删标签 <ID> <标签...>` | 删除标签 |
| `/图库 删除 <ID>` | 移入回收站（管理员或上传者） |
| `/图库 启用 / 禁用 <ID>` | 控制是否参与随机/自动发送（管理员） |
| `/图库 学习模式 开\|关` | 本会话自动学习图片（管理员） |
| `/图库 自动 开\|关` | 本会话自动发图（管理员） |
| `/图库 赞 / 踩 [ID]` | 评价图片；不写 ID 时评价最近自动发送的图 |
| `/图库 统计` | 数量、占用、使用次数、热门标签 |
| `/图库 回收站 [页码]` | 查看可恢复的删除记录（管理员） |
| `/图库 恢复 <ID>` | 从回收站恢复（管理员） |
| `/图库 修复` | 清理失效索引、移走孤立文件（管理员） |
| `/图库 清理` | 按上限裁剪并清理过期回收站（管理员） |
| `/图库 清空 confirm` | 清空图库到回收站（管理员） |
| `/图库 清空回收站 confirm` | 永久删除回收站内容（管理员） |

说明：

- `ID` 可以只写 `#` 后面的 8 位，例如 `#ab12cd34` 写成 `ab12cd34`。
- `|` 或 `｜` 后面是描述，可以包含空格。
- 没有写标签时使用 `未分类`；自动学习时没有文字说明的图片会跳过。
- 单条消息最多处理 5 张图片，避免平台消息过大。

## 自学习是怎么工作的

这里的“自学习”是轻量级的标签/反馈学习：不调用视觉模型，也不会产生额外模型费用。它依赖你给的标签、图片说明和用户反馈来逐渐调整图库。

### 1. 显式学习

`/图库 学习 猫 橘猫 | 睡觉的橘猫`：立即入库，标签和描述都来自你。

### 2. 学习模式

管理员发送 `/图库 学习模式 开` 后，本会话内所有**带文字说明**的图片都会自动入库：

- 文字说明保存为 `caption`；
- 说明中的 `#标签` 和短语会变成标签；
- 没有文字的图片不会保存，避免存一堆无法检索的图；
- 重复图片只合并标签。

关闭：`/图库 学习模式 关`。

> 学习模式和自动发图开关按会话隔离；图库本身默认是全局共享的，其他会话也能搜索/随机到已入库图片。数据落盘在插件自己的 `data/plugin_data/` 目录。

### 3. 反馈学习

开启自动发图后，机器人会记住最近一次自动发送：

- 3 分钟内回复“好可爱”“不错”“谢谢”等，图片的 `likes` 增加，并把回复中的短词学习成新标签；
- 回复“不对”“别发”“难看”等，`dislikes` 增加，该图片 1 小时内降低推荐；
- 也可以显式 `/图库 赞 <ID>` / `/图库 踩 <ID>`。

这是轻量级的“使用中学习”，不依赖大模型，也不会额外产生 API 费用。

## 自管理

- **去重**：按 SHA-256 内容哈希识别，重复上传只合并标签和描述。
- **容量控制**：超过 `max_images` 时，优先移除“旧、使用少、评价低”的图片，新上传图片有 10 分钟保护期。
- **回收站**：删除不是立即永久删除；默认保留 7 天，可恢复。
- **修复**：索引存在但文件丢失、文件存在但索引丢失，都会在 `/图库 修复` 中处理。
- **原子写入**：索引和状态使用临时文件 + `os.replace`，避免断电/崩溃留下半个 JSON。
- **权限**：管理员、上传者、普通成员的操作边界由配置控制；额外管理员 ID 可解决部分平台没有管理员角色的问题。

## 数据与隐私

数据目录（AstrBot 4.9.2+ 推荐；旧版本会回退到当前工作目录下的 data/）：

```text
data/plugin_data/astrbot_plugin_smart_image/
├── index.json        # 图片元数据
├── state.json        # 每个会话的学习/自动开关、冷却、反馈状态
├── library/          # 图片原文件，文件名为随机 ID
└── trash/            # 回收站，按记录分目录
```

- 图片以原始字节保存，不主动改写/压缩，避免损失画质；也意味着不会自动清除 EXIF。对隐私敏感的部署请在入口侧处理。
- 插件不会把图片上传到第三方；链接导入是机器人服务器直接请求你给的 URL。
- 学习模式是管理员显式开启的会话级功能，请先告知群成员。
- 默认阻止链接导入内网/保留 IP，降低 SSRF 风险。

## 全平台说明

插件只依赖 AstrBot 的通用消息组件：

```python
Comp.Image.fromFileSystem(path)
event.chain_result([...])
```

因此平台适配器会自行处理“本地文件 / URL / base64”的转换。少数平台或部署方式要求图片必须是公网 URL，可按需开启：

- `use_file_service: true`：尝试调用 AstrBot 的文件服务，把本地图片注册成带 token 的 URL；失败自动回退本地文件。需要 AstrBot 配置了 `callback_api_base`。
- `public_base_url`：你自己的反向代理/对象存储前缀，插件会发送 `前缀/文件名`。需要把该路径映射到 `library/` 目录。

默认配置使用本地文件，适配大多数 AstrBot 部署。

## 常见问题

**上传后提示“仅支持 JPG、PNG、GIF、WebP、BMP”**

部分平台会把图片转成其他格式（如 HEIC/AVIF），或消息里只有缩略图。可以尝试重新发送原图，或先用 `/图库 链接` 导入。插件只接受可被主流平台稳定发送的位图格式，避免把 SVG/HTML 当图片存储。

**群聊里不自动发图**

默认 `auto_send_require_wake: true`，需要 @机器人 或使用唤醒词；同时确认管理员已在本会话执行 `/图库 自动 开`。

**图片发送失败，提示文件丢失**

运行 `/图库 修复`。如果 `library/` 被手动清理过，索引会被修正；能恢复的文件在回收站 `_orphans` 目录。

**平台要求公网 URL**

开启 `use_file_service`（需要 AstrBot callback API），或配置 `public_base_url` 并自行做静态映射。

**想彻底重置**

先 `/图库 清空 confirm`，再 `/图库 清空回收站 confirm`。也可以停用插件后删除 `data/plugin_data/astrbot_plugin_smart_image/`。
